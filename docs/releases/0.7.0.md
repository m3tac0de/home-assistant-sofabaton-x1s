# Sofabaton X 0.7.0

This release brings a full-page remote to the Home Assistant sidebar,
lets X2 users switch Wifi Commands between HTTP and MQTT, and improves
connections on hosts with multiple network interfaces. It also includes
many fixes to hub editing, backup and restore, and the Virtual Remote.

Changes below are relative to integration **0.6.9**, including changes
previously available in the 0.7.0 test releases.

## New features

- **Sofabaton X in the sidebar.** Enable **Sidebar Panel** in Control
  Panel settings for *All users* or *Admins only*. The full-page remote
  has a navigation wheel, volume/channel controls, activity and device
  selection, and sheets for favorites, macros and device commands. It
  adapts to portrait and landscape screens and supports holding keys to
  repeat. Administrators can switch to the Control Panel in the same
  page; other users see only the remote. Link directly to
  `/sofabaton-x/virtual-remote` or `/sofabaton-x/control-panel` from a
  dashboard to open that view with a back arrow.
- **Change X2 Wifi delivery.** Switch individual managed Wifi Devices
  and the shared Wifi Events device between HTTP and MQTT. The
  integration verifies the replacement and moves activity references
  before deleting the old device. Nothing switches automatically.
  See [delivery setup and switching](../wifi_commands.md#changing-the-delivery-method).
- **Choose the local IP address for each hub.** Automatic selection now
  handles multi-interface and policy-routed hosts more reliably. Use
  the per-hub local address setting when you need to choose the address
  the hub connects back to. Thanks to @jkoelker for the multi-interface
  networking contribution. See [networking](../networking.md).
- **Copy shortcuts between activities.** In an activity's Shortcuts
  editor, choose **Copy** to bring in missing favorites and macros
  from another activity, then review and sync. This also works while
  editing a backup.
- **Control Panel improvements.** Rename the hub from settings, use the
  physical remote sync shortcut in the bottom dock, and work with
  clearer button, shortcut and add/edit dialogs.

## Reliability and remote fixes

- Hub operations are coordinated per hub, failures report their actual
  outcome, and affected data is read back after interrupted writes.
  Failed operations no longer produce misleading success notices.
- Backup and restore handle missing devices, failed erases and partial
  writes more accurately. Long-press-only assignments survive a
  backup/restore round trip.
- X1 favorites and macro ordering stay complete after edits. X1S/X2
  Wifi device and command names outside Latin-1 are preserved, and
  favorite writes respect the hub's supported command-id range.
- Cache fixes prevent stale keymaps, favorites, macros and power settings
  from appearing when the hub reuses an id. Renaming an activity no
  longer loses cached device commands. Enabling persistent cache starts
  a refresh automatically.
- Connection and discovery handling recovers from network errors and
  handles non-/24 networks and multiple hubs more reliably.
- The Virtual Remote gains better contrast with glass themes, clearer
  dropdowns, corrected EXIT-button behavior and more reliable keymap
  loading. The X2 number pad also works with the separate Sofabaton Hub
  integration.
- Integration warnings and errors remain visible in Home Assistant's
  log; diagnostic logging is still available for troubleshooting.

## Updating

1. Update the integration and restart Home Assistant. Existing hubs and
   settings carry forward; the sidebar is optional.
2. Reload open Home Assistant pages to load the updated frontend.
3. If HACS manages **Sofabaton Virtual Remote** separately, update that
   card to **0.2.7** too. Updating this integration does not replace the
   HACS-managed card. Otherwise the bundled card updates with the integration.

New or changed device and activity names must fit the hub's 30-character
limit and model-specific character rules. Existing unchanged names are
preserved. Backups with cross-activity references are refused before any
write; references within an activity remain supported.

Before switching X2 delivery, configure the selected listener or MQTT
broker and save a backup. HTTP repeats held presses; MQTT sends one
resolved activation. Review automations that depend on repeated presses.
